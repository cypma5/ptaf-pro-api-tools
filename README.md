# PTAF PRO API Client

Клиентская утилита для работы с API PTAF PRO 4.x (в т.ч. 4.3.0). Позволяет управлять правилами, шаблонами политик, настройками трафика, действиями в правилах, конфигурациями тенантов и копировать объекты между тенантами.

---

## ⚠ Предупреждение

**Использование утилиты может приводить к ошибкам в работе и переводить инсталляцию PTAF в неработоспособное состояние.**

- Операции изменяют конфигурацию напрямую через API (правила, шаблоны, приложения, списки и т.д.).
- При сбоях сети, несовместимости версий API или ошибках в данных возможны частичные применения изменений, дубликаты или потеря настроек.
- Рекомендуется делать резервные копии конфигурации (снапшоты) до массовых операций и тестировать изменения в тестовой среде.

---

## Функционал

### Главное меню

1. **Работа с правилами** — импорт/экспорт пользовательских правил (в т.ч. с сохранением связей с действиями и состоянием включено/выключено), удаление всех пользовательских правил.
2. **Управление шаблонами и политиками безопасности** — просмотр наборов правил и шаблонов, создание шаблонов, экспорт/импорт шаблона в JSON, копирование шаблона в другой тенант, создание шаблона на основе политики.
3. **Управление настройками traffic_settings** — настройки NGINX (размер загрузки, логи), Envoy (sticky session, TLS), лимиты приложений, debug-режим.
4. **Управление действиями в правилах** — замена/добавление конкретных действий в правилах выбранного тенанта (Log to DB, Custom Response, Syslog и др.), в т.ч. экспериментальные варианты (любое действие ко всем правилам, замена/удаление по имени).
5. **Получение конфигураций тенантов** — снапшот текущего или выбранного тенанта, снапшоты со всех доступных тенантов (GET config/snapshot).
6. **Восстановление конфигураций тенантов** — восстановление конфигурации безопасности из выбранного файла снапшота (с подтверждением).
7. **Копирование объектов между тенантами**:
   - Копирование защищаемых серверов (бекендов) в другой тенант
   - Копирование ролей в другой тенант
   - Копирование пользовательских действий в другой тенант
   - **Копирование веб-приложения в другой тенант (экспериментальное)** — данные приложения и переназначения правил всегда берутся из снапшота исходного тенанта (GET config/snapshot); копируются приложение, шаблон политики (при отсутствии в целевом тенанте), оверрайды системных и пользовательских правил по именам; опционально сравнение снапшотов после переноса.
8. **Работа с тенантами** — выбор и переключение тенанта, просмотр списка тенантов.
9. **Управление глобальных списков** — работа с глобальными списками (доступно при PTAF 4.2.2+).
10. **Выход**

Часть пунктов меню отображается в зависимости от версии PTAF (например, глобальные списки — с 4.2.2).

## Установка

Клонируйте репозиторий и при необходимости создайте виртуальное окружение:

```bash
git clone <repository-url>
cd ptaf-pro-api-tools
# опционально: python3 -m venv venv && source venv/bin/activate  # Linux/macOS
pip install -r requirements.txt   # если есть зависимости
```

---

## Конфигурация

Создайте или измените конфигурационный файл `ptaf_api_client_config.json` (по умолчанию ищется в каталоге скрипта):

```json
{
  "ptaf_url": "https://your-ptaf-server",
  "username": "login",
  "password": "password",
  "api_path": "/api/ptaf/v4",
  "verify_ssl": false,
  "ssl_cert_path": null
}
```

- `ptaf_url` — базовый URL сервера PTAF PRO  
- `username` / `password` — учётные данные для получения JWT  
- `api_path` — путь к API (обычно `/api/ptaf/v4`)  
- `verify_ssl` — проверять ли SSL-сертификат  
- `ssl_cert_path` — путь к сертификату (если нужен)

## Использование

### Интерактивный режим (по умолчанию)

```bash
python3 ptaf_api_client.py
```

После входа отображается главное меню. Для части операций потребуется выбрать тенант. Версия PTAF запрашивается при старте и влияет на доступные пункты меню.

### Режим CLI (опции)

```bash
python3 ptaf_api_client.py [опции]
```

| Опция | Описание |
|-------|----------|
| `--config FILE` | Путь к конфигурационному файлу (по умолчанию `ptaf_api_client_config.json`) |
| `--debug` | Включить отладочный режим (полные запросы/ответы) |
| `--source DIR` | Импорт правил из указанной директории |
| `--export` | Экспорт правил (с запросом сохранения связей с действиями и состояния) |
| `--delete-all` | Удалить все пользовательские правила (с подтверждением) |
| `--snapshot` | Создать снапшоты конфигурации по всем доступным тенантам |
| `--policy-template` | Управление шаблонами политик |
| `--traffic-settings` | Управление traffic_settings |
| `--actions` | Управление действиями в правилах |
| `--restore` | Восстановление конфигурации из снапшота |
| `--transfer` | Копирование объектов между тенантами |
| `--tenants` | Работа с тенантами |
| `--global-lists` | Управление глобальными списками (PTAF 4.2.2+) |
| `--rules` | Работа с правилами |
| `--dangerous` | Опасные действия |

При использовании опций выполняется соответствующее действие без вывода главного меню (при необходимости запрашивается тенант или путь).

## Ограничения и известные проблемы

- **Экспорт/импорт правил с динамическими списками** — могут работать не во всех сценариях.
- **Перенос шаблона политики** — при наличии изменённых правил с системными динамическими списками возможны ошибки; маппинг глобальных списков выполняется по имени и типу (включая системные списки).
- Поведение API может отличаться в зависимости от версии PTAF и типа тенанта (agent/worker); часть функций помечена как экспериментальная.
